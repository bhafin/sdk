# Security reporting

Do not include credentials, customer records, financial account data, or exploit details in a public issue or pull request.

Before opening this repository to the public, maintainers must enable private vulnerability reporting through the repository's Security advisories and verify that reports reach the responsible maintainer. A verified private reporting channel is a release prerequisite. No reporting email or response-time commitment is established here.

Once enabled, use **Security → Report a vulnerability** for a private report. If that option is absent, do not post sensitive details publicly; ask the repository maintainer to enable private reporting first.

Include the affected SDK version/runtime, a minimal synthetic reproduction, expected and observed behavior, and impact. Redact tokens, keys, account identifiers, and customer data. No live service access is required to demonstrate most SDK issues.

There are no publicly released supported SDK versions yet. Version support and a security maintenance policy must be established before the first public package release.
